## 先看一条查询

```sql
SELECT id, name FROM users WHERE email = 'hello@example.com';
```

没有适用索引时，数据库可能需要逐行检查数据。随着表变大，要检查的行也会增加。索引为特定字段维护了另一种组织方式，让数据库有机会直接缩小查找范围。

## B+ 树如何帮助查找

InnoDB 的常见索引结构是 B+ 树。非叶子节点用于导航，叶子节点保存对应的记录信息。一次查找从根节点开始，逐层缩小范围，最终定位叶子节点。

同一页中可以保存多个索引项，因此树通常不需要很高。相邻叶子页之间有链接，也便于范围扫描。

## 聚簇索引与二级索引

InnoDB 通过聚簇索引组织行数据；通常使用主键作为聚簇索引的键。二级索引的记录包含二级索引列和对应主键值。

当二级索引已经包含查询所需的信息时，可以利用覆盖索引减少读取。如果还需要其他列，通常要根据主键进一步查找完整记录，这就是常说的回表。

## 索引也有成本

索引占用存储空间，写入、删除和更新时也需要维护。索引越多，并不意味着整体性能越好。

为哪些列建立索引，应结合真实查询条件、排序需求、数据分布和执行计划判断。对于需要返回大量行的查询，优化器也可能选择全表扫描。

## 用执行计划验证

```sql
EXPLAIN SELECT id, name
FROM users
WHERE email = 'hello@example.com';
```

观察访问方式、选择的索引和估算行数，并结合实际执行时间分析。调整前后使用相近的数据与环境，才更容易判断优化是否有效。
